# Аким на 5 часов

Симулятор городского управления: пять направлений, единый стартовый бюджет и прозрачная оценка последствий для районов Астаны. Свободный выбор мероприятий; интерфейс со стилизованной картой, без игровых миссий и наград.

## Запуск

Node.js 22 (`.nvmrc`) и npm:

```sh
npm ci
npm run dev
```

Открыть http://localhost:3000. Расчёты, карта и события работают без ключей. Для остальных сервисов скопировать `.env.example` в `.env.local` и настроить серверные переменные:

- `OPENAI_API_KEY`, опционально `OPENAI_MODEL` — объяснения, рекомендации и текст презентации.
- `PARTICIPANT_SECRET` (не менее 32 случайных символов), `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` — общее хранилище рейтинга.
- Альтернатива Upstash-паре: `KV_REST_API_URL` / `KV_REST_API_TOKEN` от Vercel Marketplace. Пары нельзя смешивать.

Секреты не передаются браузеру и не коммитятся. При отсутствии AI доступны рассчитанный Score, проверенные численные рекомендации и шесть расчётных/служебных слайдов; приложение явно сообщает, что AI недоступен. Без хранилища рейтинг показывает ошибку с повторной загрузкой, а не фиктивные результаты.

## Реализация требований

| Требование                          | Где и как работает                                                                                                                                                                                                   |
| ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Единый виртуальный бюджет           | Всем участникам по 100 единиц; расходы независимы. Остаток в шапке и блоке сценария.                                                                                                                                 |
| Решения по пяти направлениям        | Все пять направлений, 14 мероприятий, выбор районного/городского охвата. По authoritative dataset: ровно пять разных мер, максимум две одного направления.                                                           |
| Контроль превышения бюджета         | Общий валидатор блокирует недопустимый выбор в UI; сервер проверяет повторно. Замена, удаление и несовместимости учитываются.                                                                                        |
| AI-анализ                           | «Рассчитать сценарий»: `/api/catalog` → `/api/simulate` → `/api/analyze`. Ключ только на сервере.                                                                                                                    |
| Astana Quality of Life Score        | Детерминированный общий модуль, подтверждение сервером. AI не выставляет баллы.                                                                                                                                      |
| Сильные стороны, риски, последствия | Структурированный AI-отчёт с раскрываемыми фактами и метаданными; корректная обработка недоступности.                                                                                                                |
| Сравнение команд                    | Вкладка «Сравнение»: чтение рейтинга, явная публикация с именем, личный лучший результат, равные места, собственная строка, пагинация. Реальный Redis, никаких данных-фикстур в приложении.                          |
| Визуализация изменений              | Карта «До / После», маркеры мер, дельты районов и показателей, диаграмма индексов в результате.                                                                                                                      |
| AI-рекомендации                     | Проверенные сервером замены, выигрыш/расходы, AI-обоснование с фактами. Перед применением снова проверяется исходный сценарий; старый отчёт сбрасывается.                                                            |
| Неожиданные события                 | Каталог и случайный выбор через API. Резерв 5/10 из 100, отдельный редактируемый план, запрет недопустимого Score, серверный пересчёт. Основной план не изменяется, результат события не идёт в стандартный рейтинг. |
| Презентация                         | Просмотр 9 слайдов с AI или 6 без AI, навигация, экспорт Markdown. PPTX/PDF пока не реализованы.                                                                                                                     |

Подробности контрактов: [docs/features.md](docs/features.md). API обработки отзывов также интегрирован, но отдельный UI экспериментальной проекции не входит в перечисленные требования.

## Дизайн и карта

Сине-золотая палитра, знак шанырака и сдержанный орнамент. Разделы: карта и карточка района → сценарий → результат и дополнительные инструменты. [Visit Astana](https://visitastana.kz/en/map/) использован как ориентир композиции карты, переключателей и ленты карточек, без копирования оформления.

Карта упрощена до основных дорог, реки, парков и 60 условных объёмных построек. Крупные ориентиры помогают узнавать Астану. Кварталы и пять зон иллюстративные, не официальный административный план. Перетаскивание прекращается на pointerup, pointercancel и lostpointercapture; наведение не двигает карту. Размер SVG уменьшен с 3 895 427 до 105 963 байт.

[Источники, лицензия и пересборка карты](docs/map.md). Скриншоты production-сборки: [главный экран](docs/ui/desktop.png), [мобильная версия](docs/ui/mobile.png), [выбор мероприятия](docs/ui/choose-decision.png), [расчётные рекомендации без AI](docs/ui/recommendations.png).

## Проверки

```sh
npm run typecheck
npm run lint
npm test
npx playwright install chromium
npm run test:e2e
npm run build
```

131 unit/API-тест и 12 браузерных сценариев. Браузерные проверки используют настоящий сервер для симуляции и событий; платные AI-запросы и внешний Redis заменены только на транспортной границе тестов. Проверены зависание карты после отпускания, мобильный выбор, лимиты, сохранение, AI-факты/кэш, рекомендации и устаревшие ответы, события, презентация/скачивание, публикация и ошибки рейтинга.

Контрольный пример: стоимость 95, исходный Score 52.55768, итог 56.54307, критических значений после мер — 0. Формула и правила берутся из [dataset/dataset.json](dataset/dataset.json); [описание модели](docs/model.md), [AI](docs/ai.md).

## Демо

1. Значок помощи → «Загрузить контрольный пример · 95 ед.».
2. На карте выбрать «После решений», раскрыть показатели района.
3. «Рассчитать сценарий»: ожидаемый Score 56,54 и AI-отчёт при доступном ключе.
4. «Рекомендации» → «Найти улучшения» → применить вариант; оценка изменится, прежний отчёт сбросится.
5. Снова загрузить пример; «События» → «Сильные осадки»: перерасход 5. Заменить M5 на M4, рассчитать. Меры 85 + резерв 10, остаток 5; основной сценарий остаётся 95.
6. «Презентация» → сформировать → пролистать → скачать Markdown.
7. На окружении с Redis: «Сравнение» → задать имя → явно опубликовать. Во втором браузере проверить общий список и независимый бюджет.

## Совместная работа и публикация

Перед этапом fetch всех веток и pull текущей; после проверок commit и push. Границы ответственности — [AGENTS.md](AGENTS.md). В `codex/ui` объединены contracts, dataset-prep, resident-feedback, scenario-features и совместимые исправления codex/deploy. Backend второго разработчика не дублируется во frontend.

Ранее опубликованный сайт: https://akim-five-hours.vercel.app. Эта переработка доступна в `codex/ui`; **push сам по себе не обновляет публичный сайт**, автодеплой не подключён. Актуальный статус публикации — [docs/deployment.md](docs/deployment.md).

Проверка настоящего AI и рейтинга новой версии согласована на окружении второго разработчика. Там следует подтянуть `codex/ui`, запустить проверки и сборку, проверить UI со своим серверным окружением и затем обновить deployment. На устройстве разработчика 1 секреты отсутствуют. Read-only запросы опубликованных `/api/catalog`, `/api/events`, `/api/leaderboard` прошли; платные запросы и публичные записи этим этапом не создавались. Прежние live-проверки backend перечислены в docs/deployment.md.
