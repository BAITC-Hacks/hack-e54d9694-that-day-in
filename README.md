# Аким на 5 часов

Учебный симулятор управления Астаной: пять решений, бюджет 100 единиц и оценка последствий для пяти районов.

## Текущий этап

Главный экран — географическая игровая карта Астаны и одна карточка следующего шага. В основе карты реальные дороги, водоёмы, парки и здания OpenStreetMap; объём и достопримечательности стилизованы. Есть перемещение, приближение, пять игровых зон и инфраструктура на приближении. Карта работает без внешнего сервиса и отдельного API-ключа. Географические ограничения, лицензия и воспроизведение описаны в [docs/map.md](docs/map.md).

Путь игрока: выбрать район → увидеть потребность → выбрать одно мероприятие → увидеть изменение бюджета и маркеры на карте → получить результат пяти решений. Каталог сначала показывает одно направление, все 14 мер доступны отдельно. Десять показателей района и список решений раскрываются по запросу. Выбор можно отменить, черновик сохраняется. Footer содержит информацию об игре, правила и источник карты.

Расчёты и ограничения исходного датасета сохранены. Перед AI-анализом сервер проверяет версию данных и решения. Готовые AI-отчёты сохраняются локально (последние десять); повторное открытие того же сценария использует сохранённый текст после повторной проверки расчёта сервером.

AI без ключа недоступен: приложение показывает причину, сохраняет числовой результат и позволяет повторить запрос. Успешное отображение AI проверено автоматизированным тестом с явно тестовым ответом; живой полный AI-анализ на устройстве разработчика 1 пока не проверен из-за отсутствующего ключа.

## Локальный запуск

Скриншоты рабочей production-сборки: [настольный экран](docs/ui/desktop.png), [мобильный экран](docs/ui/mobile.png).

Проверенный этап: 59 unit/API-тестов, 6 браузерных сценариев, typecheck, ESLint и production build. HTTP-проверка production-сервера подтверждает каталог, контрольный Score и серверную валидацию. Проверка живого AI на устройстве разработчика 2 описана отдельно в [docs/ai.md](docs/ai.md).

Требуется Node.js 22 и npm. Версия Node указана в `.nvmrc`.

```sh
npm ci
npm run dev
```

Откройте http://localhost:3000. Для карты, каталога и расчётов API-ключ не нужен. Для AI скопируйте `.env.example` в `.env.local` и задайте серверный `OPENAI_API_KEY`. Никогда не коммитьте ключ. В режиме разработки используйте hostname `localhost`, как в браузерных тестах: Next.js ограничивает доступ к dev-ресурсам с других origins.

## Проверки

```sh
npm run typecheck
npm run lint
npm test
npx playwright install chromium
npm run test:e2e
npm run build
```

Unit/API-тесты проверяют исходные данные, ограничения, лаги, синергии, Score, серверную валидацию и AI-ошибки. Браузерные тесты проверяют последовательное раскрытие интерфейса, загрузку карты, перемещение и зум, каталог, мобильный выбор и отмену, контрольный пример, сохранение плана, блокировку несовместимых и дорогих мер, обработку HTTP 503, отображение объяснений и повторное использование отчёта. Автоматические тесты не обращаются к платной модели: браузерные проверки используют настоящий API расчёта и подменяют только ответ AI.

## Источник истины

Исходные данные и правила: [dataset/dataset.json](dataset/dataset.json), [описание датасета](dataset/README.md).

- Пять районов, десять показателей, четырнадцать мероприятий.
- Бюджет 100; ровно пять разных мероприятий, не более двух одного направления.
- Районные меры требуют район; городские действуют во всех районах.
- Горизонт восемь кварталов, эффект уменьшается с учётом лага; синергии лагом не масштабируются.
- Score = 0,7 × средний индекс + 0,3 × минимальный индекс − число показателей ниже 40.
- AI объясняет результат, не выставляет баллы.

Контрольный пример: цена 95, исходный Score 52.55768, результат 56.54307, критических значений после мер — 0. Вёрстка не содержит собственной реализации этой формулы.

## Совместная разработка

Перед каждым этапом: fetch всех веток, pull текущей upstream-ветки, проверка изменений в main и codex-ветках. После проверенного этапа: commit и push. Подробные границы ответственности — в [AGENTS.md](AGENTS.md).

В `codex/ui` интегрированы актуальные контракты из `codex/contracts`, расчётный модуль и API из обновлённой `codex/dataset-prep`. Отменённый каталог шести районов не используется.

Для моментального просмотра интерфейс использует общий валидированный JSON и общий расчётный модуль. Перед оценкой он получает версию через `GET /api/catalog`, проверяет соответствие встроенных данных и отправляет решения в `POST /api/simulate` и `POST /api/analyze`. При изменении серверного датасета требуется обновление страницы. Владелец расчётов, API и AI — разработчик 2; [описание модели](docs/model.md), [API и AI](docs/ai.md).

## Быстрая демонстрация

1. Откройте правила через значок вопроса.
2. Нажмите «Загрузить контрольный пример · 95 ед.».
3. Изучите прогноз районов, значки решений на карте и оставшиеся 5 единиц бюджета.
4. Нажмите «Посмотреть результат»: ожидается 56,54 после округления для интерфейса.
5. При настроенном ключе появится AI-отчёт; без ключа числовой результат останется доступным.
6. Откройте «Мой план», удалите мероприятие, выберите район на карте и другую меру в каталоге. Повторите оценку.

## Публикация

Проект подготовлен для Vercel: framework Next.js, Node.js 22, install `npm ci`, build `npm run build`. Секреты задаются в настройках окружения платформы. Публичная ссылка будет добавлена после успешного деплоя.

Новые экспериментальные ветки `codex/resident-feedback` и `codex/scenario-features` проверены при обновлении GitHub. Они остаются отдельными: текущий этап меняет игровой интерфейс, не вводит дополнительные режимы или новый расчёт состояния города.
