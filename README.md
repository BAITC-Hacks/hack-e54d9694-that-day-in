# Аким на 5 часов

Учебный симулятор управления Астаной: пять решений, бюджет 100 единиц и оценка последствий для пяти районов.

## Текущий этап

Реализован первый интерфейс на настоящем `dataset/dataset.json`: изометрическая SVG-карта пяти районов, выбор района, десять показателей, фильтры направлений, каталог 14 мероприятий, правила и адаптивный экран.

Показатели и Score на экране — исходное состояние из датасета. Выбор мероприятий, расчёт прогноза, сохранение сценария и AI-отчёт подключаются следующим этапом. Кнопка оценки намеренно недоступна; приложение не имитирует расчёт или AI.

## Локальный запуск

Требуется Node.js 22 и npm. Версия Node указана в `.nvmrc`.

```sh
npm ci
npm run dev
```

Откройте http://localhost:3000. Для карты и каталога API-ключ не нужен. Для будущего backend скопируйте `.env.example` в `.env.local` и задайте серверный `OPENAI_API_KEY`. Никогда не коммитьте ключ.

Браузерные тесты проверяют переключение районов и категорий, полный каталог, работу диалогов, клавиатурный выбор и отсутствие горизонтального переполнения на мобильном экране. Пока unit/API-тесты второго разработчика не интегрированы, `npm test` допускает отсутствие таких тестов; это не свидетельство проверки расчётного модуля.

## Источник истины

Исходные данные и правила: [dataset/dataset.json](dataset/dataset.json), [описание датасета](dataset/README.md).

- Пять районов, десять показателей, четырнадцать мероприятий.
- Бюджет 100; ровно пять разных мероприятий, не более двух одного направления.
- Районные меры требуют район; городские действуют во всех районах.
- Горизонт восемь кварталов, эффект уменьшается с учётом лага; синергии лагом не масштабируются.
- Score = 0,7 × средний индекс + 0,3 × минимальный индекс − число показателей ниже 40.
- AI объясняет результат, не выставляет баллы.

Контрольный пример: цена 95, исходный Score 52.55768, результат 56.54307, критических значений после мер — 0. Вёрстка не содержит собственной реализации этой формулы.

## Совместная разработка

Перед каждым этапом: fetch всех веток, pull текущей upstream-ветки, проверка изменений в main и codex-ветках. После проверенного этапа: commit и push. Подробные границы ответственности — в [AGENTS.md](AGENTS.md).

В `codex/ui` интегрированы актуальные контракты из `codex/contracts` (c4b8ca1). Старый каталог из `codex/dataset-prep` не используется: он относится к отменённой модели шести районов и Score 80/20.

Интерфейс сейчас читает исходный JSON напрямую. При интеграции backend источником станет `GET /api/catalog`, а запросы `POST /api/simulate` и `POST /api/analyze` будут использовать общие контракты. Владелец расчётов, API и AI — разработчик 2.
