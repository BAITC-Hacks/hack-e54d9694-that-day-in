Платформа: Vercel, framework Next.js, Node.js 22.x (из package.json),
установка `npm ci`, сборка `npm run build`.
`.vercelignore` исключает локальные секреты и артефакты из загрузки исходников.

Переменные окружения сервера:

- `OPENAI_API_KEY` — существующий ключ, не передавать в браузер или Git;
- `OPENAI_MODEL=gpt-5.4-mini-2026-03-17`;
- `PARTICIPANT_SECRET` — случайный секрет не короче 32 символов;
- `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` — общее хранилище рейтинга.

На опубликованном проекте Upstash Marketplace автоматически установил
`KV_REST_API_URL` и `KV_REST_API_TOKEN`; сервер поддерживает эту пару имён.
Ресурс `akim-leaderboard`: бесплатный тариф, регион fra1, autoUpgrade=false,
eviction=false. Ключ AI и PARTICIPANT_SECRET настроены как серверные секреты.

Не скачивать настройки хостинга поверх существующего `.env.local`.
После настройки переменных нужен новый deployment.
Без Redis обычная симуляция и AI могут работать, но `/api/leaderboard` возвращает 503.
В интерфейсе подключены рекомендации, события, сравнение и презентация;
контракты и правила находятся в [features.md](features.md).

При подключении автодеплоя production-веткой следует выбрать `main`, где собрана
интегрированная версия. Пока эта настройка не выполнена, push в GitHub не обновляет
production-сайт.

Проверки после деплоя: открыть главную страницу и `/api/catalog`, отправить
контрольный сценарий в `/api/simulate` (95 / 56.54307 / 0), выполнить настоящее

и блокировкой до загрузки состояния. Добавлены регрессионные проверки на 1440 и 390 px:

размерах экрана: JavaScript-ошибок и горизонтального переполнения нет.

## Историческая диагностика лагов карты (исправлена в 507e847)

Первый разработчик уменьшил подложку до 105 963 байт и исправил завершение жеста.
Регрессионная проверка остановки карты после отпускания мыши включена в прошедшие
14 браузерных тестов. Ниже исходные замеры предыдущей версии.

Проверено на production 23.09.2026 в Chromium, viewport 1440×1000:

- `public/maps/astana.svg`: 3 895 427 байт исходного SVG, около 1 046 886 байт по сети;
- при перетаскивании: 38 из 80 интервалов кадров дольше 50 мс, отдельные задачи 100–245 мс;
- в диагностической копии DOM без фонового SVG тот же drag: максимум 16.8 мс, 0 длинных задач;
- обычные HTTP-запросы страницы с CDN HIT: 74–274 мс (первый запуск браузера был медленнее);
- подтверждён баг: камера продолжает двигаться после mouseup без нажатой кнопки.

Причина последнего: CityMap.pointerMove сохраняет активный drag, а onPointerUp
только освобождает capture. Нужно завершать жест, проверять e.buttons и сохранять
отдельное подавление клика после drag. Учесть pointercancel/lostpointercapture.
Для производительности требуется облегчить статическую подложку (например,
растр подходящего разрешения или упрощённая геометрия), ограничить обновления
камеры одним кадром и изолировать неподвижные слои от частых React-рендеров.
Диагностическое удаление подложки не сохранено в исходниках. UI-файлы в этой
ветке не исправлялись: карта остаётся областью первого разработчика.
