# AI и серверный API

## Публичный протокол

`GET /api/catalog` → 200, тело Catalog без обёртки. `POST /api/evaluate` принимает EvaluateRequest (три версии и объект selections). Успех → 200 Evaluation, status `complete`. Ошибка сценария → 422 ValidationError; несовпадение версий → 409 ValidationError. В этих случаях AI не вызывается.

Недоступность AI → 503 Evaluation, status `ai_unavailable`, с сохранённым simulation и evidence. aiAssessment, aiPoints, finalScore равны null; aiError содержит безопасную причину. UI должен прочитать тело ответа даже при `response.ok === false`. Не заменять его fixture или нулевым баллом. Повторная попытка — явный новый запрос пользователя.

Ожидаемые импорты UI: типы/схемы из `src/shared/contracts.ts`; тестовые данные из `src/shared/fixtures.ts`. Fixtures помечены как тестовые; model=`fixture-no-ai-call`. Общие модули не зависят от OpenAI или серверного окружения.

## OpenAI

Только сервер: официальный SDK `openai`, Responses API, Structured Outputs через `zodTextFormat`. Начальная модель `gpt-5.4-mini-2026-03-17`, env `OPENAI_MODEL`. `OPENAI_API_KEY` не должен иметь префикс NEXT_PUBLIC, попадать в Git, клиентский bundle или логи. Для локального запуска — `.env.local`; для деплоя — серверная переменная Vercel. Ключ не передаётся браузером в evaluate.

Нужны зависимости `zod@4`, `openai@6`; для тестов `vitest@3`. Их добавляет владелец каркаса. Общая платформа — Node.js 22, runtime nodejs. Обработчик должен экспортировать `maxDuration=60`; лимит одной оценки AI — 45 секунд включая ожидание. Скрытые повторные попытки SDK отключены (`maxRetries: 0`). Серверного хранилища и кэша оценок нет.

Справка: [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [GPT-5.4 mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini). Документация подтверждает Responses и структурированный вывод; фактический доступ зависит от ключа проекта.

## Рубрика v1.0.0

Каждый критерий получает целое число 0–5:

- needs — соответствие исходным дефицитам;
- equity — распределение выгод по районам;
- coherence — согласованность программ и межотраслевых последствий;
- feasibility — сроки и управленческие риски в рамках синтетических данных.

0 — провал; 1 — существенные проблемы; 2 — частичное соответствие; 3 — приемлемо с заметными ограничениями; 4 — хорошо с небольшими ограничениями; 5 — сильный результат, подтверждённый данными.

AI получает факты с ID: исходные метрики и население; выбранные программы, стоимость, сроки, риски и компромиссы; рассчитанные after/delta; бюджет и распределение выгод. Возвращает summary, четыре критерия с explanation и evidenceIds, по 2–3 пункта strengths/risks/consequences. Каждый пункт содержит explanation и evidenceIds. Сервер проверяет структуру, диапазоны и существование всех ссылок.

В промпте запрещено придумывать цены, эффекты и факты о реальной Астане. Предположения должны быть названы предположениями. AI не меняет метрики и не считает итоговый балл. Проверка ссылок доказывает наличие факта, но не гарантирует истинность каждого предложения; это ограничение экспертного текста.

## Воспроизводимость

scenarioKey зависит от трёх версий и канонического выбора пяти programId, не от порядка кликов. Он идентифицирует входной сценарий, а не детерминированный AI-ответ. Независимые повторные обращения могут дать разные оценки. Отчёт хранит модель, версии промпта/рубрики и время; сохранение отчётов выполняет клиент.
