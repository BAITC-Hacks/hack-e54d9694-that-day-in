# Карта и события

Главный экран: мероприятия слева, прежняя SVG-карта в центре, десять показателей
выбранного района «до / после» справа. На узком экране панели идут вертикально.
Отчёт, рекомендации, сравнение участников, презентация и прежний редактор
аварийных сценариев находятся во вкладке «Аналитика и сравнение».

Выбор района приближает камеру за 650 мс и ограничивает рисунок его условной
границей. «Весь город» возвращает общий вид. Поддержаны ручной масштаб,
перетаскивание и клавиатурный выбор района. Камера обновляет SVG viewBox через
requestAnimationFrame, без перерисовки всего React-дерева на каждом кадре.
Эффекты мероприятий и событий используют конечные CSS-анимации до 1,9 секунды.
При prefers-reduced-motion анимации отключены, камера перемещается сразу.

## Учебные события

Осадки, жара, сбой сервисов и ремонт можно перетащить на район или на специальную
зону «Для всего города». На телефоне и с клавиатуры: выбрать событие, затем район
на карте либо кнопку «Весь город». Попадание определяется геометрией полигона,
включая нарисованные поверх него здания. В приближённом виде цель — выбранный район.

Одновременно допускаются три события, без повторов пары event_id/district_id.
События берутся только из src/data/events.ts; цены и эффекты нельзя передать клиентом.
Ремонт улиц — новое синтетическое событие: резерв 10, T1 −3, B2 +5, C1 +6.
Сумма эффектов событий изменяет исходные показатели с ограничением 0–100, затем
существующий модуль применяет мероприятия, лаги и синергии на восемь кварталов.
Резерв уменьшает доступный личный бюджет. Недопустимое размещение не применяется;
удаление события возвращает резерв и пересчитывает показатели из исходных данных.

Исходный dataset/dataset.json не изменён. События сохраняются только в текущем
сеансе страницы. В инспекторе «до» — исходный датасет, «после» — меры плюс события.
Рейтинг и AI-анализ основного плана остаются сопоставимыми: события карты в них
не включаются. При переходе к аналитике это явно указано на экране.

## Дополнительный контракт

Существующие /api/catalog, /api/simulate, /api/analyze и contracts.ts не изменены.
В shared/features.ts добавлены MapEventPlacement, MapEventsRequest,
MapEventsResponse и MAP_EVENTS_VERSION = "1.0.0".

POST /api/events/preview принимает:

```json
{
  "dataset_version": "<версия из /api/catalog>",
  "map_events_version": "1.0.0",
  "decisions": [],
  "events": [{ "event_id": "heavy-rain", "district_id": "nura" }]
}
```

Возвращает mode=event_practice, eligible_for_leaderboard=false, события,
simulation, emergency_reserve и final_score. Для черновика final_score=null;
полный допустимый план получает расчётный Score. simulation.before отражает
исходное состояние уже после событий; для визуального сравнения с городом до
всех вмешательств UI использует исходную симуляцию отдельно.
409 — старая версия датасета, 422 — неверный формат/версия событий/превышение бюджета,
413 — слишком большой запрос. Вызовов AI нет. Браузер использует ту же чистую
simulateMapEvents для мгновенного отклика, сервер повторяет всю валидацию.

Проверки: изоляция района, городской охват, отрицательные и положительные эффекты,
ограничение показателей, независимость порядка, возврат бюджета, недопустимые цели,
подделка эффектов, неизменность контрольного Score 56.54307. Браузерные проверки
покрывают настоящее drag-and-drop, мобильный выбор события, уменьшенное движение,
масштабирование, вкладки и существующие отчёты/рейтинг с подменой только платного AI
и внешнего Redis.
