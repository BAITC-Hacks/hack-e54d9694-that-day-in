# Совместная работа

Проект делают два разработчика. Ориентир для текущей интеграции — `codex/ui`; перед началом задачи смотрите [карту веток](docs/repository.md) и актуальные PR. Рабочие договорённости для Codex находятся в `AGENTS.md` в ветке приложения.

## Перед началом этапа

1. Проверить `git status`: сохранить собственную работу и не перезаписывать чужие изменения.
2. Выполнить `git fetch --all --prune`, затем `git pull --ff-only` для текущей ветки с upstream.
3. Посмотреть изменения в `main` и других `codex/*`; объединять только совместимые изменения после просмотра diff. Если ветки разошлись, сначала разобраться в истории.
4. Для самостоятельной новой задачи использовать понятное имя `codex/<тема>`. Старые ветки не переименовывать и не удалять без согласования команды.

## Ответственность

| Область | Основной разработчик |
| :--- | :--- |
| Страница, компоненты, карта, стили, клиентские запросы и браузерные тесты | 1 · @altynbk |
| Общие контракты, адаптер данных, симуляция, AI, API и unit/API-тесты | 2 · @re1nhardd |
| README, интеграция и оформление репозитория | 1; изменения серверной документации согласуются по контрактам |
| Публикация | Из согласованной интеграции; выполненные проверки фиксируются в `docs/deployment.md` |

Изменение общего контракта нужно согласовать до независимой реализации двух сторон. Не создавать второй каталог мероприятий или альтернативную формулу Score: источник — `dataset/dataset.json`.

## Завершение этапа

- Проверить изменения подходящими для задачи проверками. Для документации достаточно ссылок, актуальности команд и отображения; для логики/интеграции — соответствующих тестов.
- Перед передачей приложения выполнить `npm run typecheck`, `npm run lint`, `npm test`, `npm run test:e2e`, `npm run build` на Node.js 22.
- Сделать осмысленный commit и push своей ветки. Force push не использовать.
- В PR описать проблему, итоговое поведение, проверки и ограничения. Для UI приложить скриншот, для API — изменение контракта.
- Указать правильную базу PR. Старые PR могут показывать цепочку разработки; их статус включения в приложение отражён в карте веток.

## Данные, секреты и проверки AI

`.env.local`, токены, cookie участников и реальные персональные данные не добавляются в Git. `.env.example` содержит только названия и пустые значения секретов. Тестовые примеры находятся отдельно от пользовательских результатов.

Обычные автотесты не расходуют AI-токены. Ручные скрипты с `--live` вызывают внешний AI и могут создавать записи в рейтинге — выполнять их только на согласованном окружении. В отчёте различать автономные тесты, проверки интерфейса с подменой запросов и настоящий внешний сервис.

## Публикация

Push и deployment — разные действия. Автодеплой GitHub → Vercel пока не подключён. Порядок публикации, текущий код на сервере и доступные переменные описаны в [docs/deployment.md](docs/deployment.md). При подготовке новой версии обновляйте этот журнал, а не удаляйте результаты предыдущих проверок.
